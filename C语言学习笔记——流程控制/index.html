C语言学习笔记——流程控制

Kanwuqing2026-10-152026-10-18

运算符与表达式最后那个计算器, 里面已经出现了 if 和 else if. 当时用得理所当然, 没解释为什么写成那样. 那篇的重点是"怎么算", 这篇要解决的是"算完之后, 程序该往哪儿走"

到目前为止写过的所有程序都有一个共同点: 从上到下, 一行一行执行到底, 中间不会拐弯. 哪怕计算器里有五个分支, 走的也是一条直线的形状, 写完一个 else if 就轮到下一个

真实程序不能这么死板. 例如输入密码要判断对错, 分数要分等级, 菜单要等用户选. 这些都需要程序能拐弯, 甚至回头. 让程序拐弯的语法, 就叫流程控制

0 综述

1 顺序结构

C 语言的语句, 默认就是从上往下依次执行, 这叫顺序结构. 之前写的一切都是这个结构:

没有任何悬念, 四行按顺序走完. 流程控制要做的, 就是在这个默认的直线上开岔路和绕圈

C 语言一共只有三种基本结构: 顺序、选择、循环. 每种结构都满足"只有一个入口、一个出口", 这是 1966 年 Bohm 和 Jacopini 证明的结论, 叫结构化程序定理. 意思是说, 无论多复杂的逻辑, 用这三种结构都能拼出来, 不需要别的花样

这个定理是 goto 后来被嫌弃的理论依据. 它能实现任意跳转, 但会破坏"一个入口一个出口", 让程序变成一团乱麻. 第 5 节中细说

2 选择结构

选择结构负责"拐弯", 也就是根据条件决定走哪条路. C 里能干这事的语句有 if、if-else、else if、switch 四个, 前三个是一家人, 最后一个单独说

2.1 if

if 是最基本的选择. 它只做一件事: 看括号里的条件成不成立, 成立就执行下面那句话, 不成立就跳过

if 后面的括号里, 常见错误是把 == 写成 =:

这行不会报错, 它的意思是"把 5 赋给 x, 然后判断 x 的值是不是非零". 5 当然非零, 所以条件永远成立

这个错误编译器只给个 -Wparentheses 警告, 默认不一定看得见. 记住一句话: 判断相等, 两个等号

2.2 非零即真

if 括号里能放的任何能算出数值的表达式, 而 C 判断真假的标准只有一条:

非零就是真, 零就是假

因为"非零即真", 所以判断"x 是不是非零"可以直接写:

2.5 switch

else if 能处理多路分支, 但写多了很难看. 比较典型的场景是菜单:

条件全是"同一个变量等于不同的值", 这种形状就适合换成 switch:

switch 括号里放一个表达式(通常是变量), 然后拿它的值去和每个 case 后面的常量比对, 命中哪个就从哪里开始执行. 全都不命中就走 default

break 在这里不能少. 忘了写就会穿透到下一个 case, 看实测:

输出是:

x 是 2, 从 case 2 进去打印 “two”, 然后没有 break, 继续往下淌, 把 case 3 的也执行了, 直到撞上那个 break 才停

这个行为叫穿透(fall-through). 它是 C 语言故意设计的, 不是 bug. 有时候确实有用(比如多个 case 共用一段代码), 但绝大多数时候是忘了写 break 导致的错误

多个 case 共用一段代码的正当写法是故意留空:

case 'a' 后面什么都没写, 直接落到 case 'A', 于是大小写都能命中同一段代码. 这叫多个 case 标号共用一个执行段

switch 有几条硬性限制:

  1. 括号里必须是整型(int char long, 以及能自动转成整型的). float double char * 都不行, 因为"相等"对它们不好定义
  2. case 后面必须是常量, 不能是变量. case n:(n 是变量)编译不过, 因为 switch 的跳转是在编译期就排好表的, 运行期才知道的值没法排
  3. default 的位置任意, 不放最后也行. 但习惯上放最后最好读
  4. switch 可以嵌套, 内层的 break 只跳出内层 switch

3 循环结构

选择结构解决了"要不要做", 循环解决的是"要不要再做一遍"

需求很常见: 求 1 到 100 的和. 按顺序结构得写 100 行加法, 显然不现实:

循环要做的是: 把"加一个数"这件事重复 100 次, 每次换一个数. C 提供三种循环, 它们能力上是等价的, 任何用 while 写的都能改成 for, 反过来也一样. 区别只在"哪种写起来更顺"

3.4 三种循环怎么选

三种循环能力等价, 所以选择标准是"哪种能最直白地表达意图":

场景 推荐 理由
已知循环次数 / 遍历一段区间 for 起点终点步长写在一行, 最清楚
次数未知, 靠条件停(读文件到结尾) while 只有条件, 硬凑三段反而啰嗦
至少要执行一次(输入校验、菜单) do-while 天生"先做后判"

4 break 与 continue

break 和 continue 都用来打断循环的正常流程, 但打断的程度完全不同:

  • break: 立刻跳出整个循环, 后面的轮次全部不做
  • continue: 立刻结束本轮, 跳回开头开始下一轮

break 一到 2 就跳出了, 3 和 4 根本没机会加进来

continue 用在 while 里要格外小心, 因为 while 的步进(比如 i++)通常写在循环体里, 一 continue 就可能跳过它:

i 到 2 时 continue, 直接回到条件检查, 而 i++ 在 continue 后面, 永远执行不到. i 卡在 2 上, 程序进入死循环. 同样的逻辑用 for 写就没这个问题, 因为 for 的 i++ 写在第三格, continue 之后仍然会执行:

break 一次只能跳出一层循环. 嵌套两层时, 内层的 break 只是结束内层, 外层照常继续:

外层转了 3 次, 每次内层在 b=0 时 cnt++, 到 b=1 就 break 出去, 所以每轮只加 1, 总共 3

想一次跳出两层, 得靠标志变量(第 3.5 节会讲), 或者 goto

break 在 switch 里的含义和在循环里不一样, 它在那里只负责"结束这个 case 的穿透", 和循环无关. 两者恰好都叫 break, 但作用对象不同

有个细节值得记一下: switch 里写 continue, 它作用于外层循环, 而不是 switch:

结果和直接在 for 里写 continue 一模一样. 因为 continue 只认循环, switch 不是循环, 它管不着

5 goto

goto 可以无条件跳到同一个函数里的某个标号处:

输出 0 1 2. loop: 是个标号, goto loop 直接跳过去, 相当于手写了一个循环

goto 能做的事, while/for 都能做, 而且做得更清楚. 所以现代 C 代码里几乎不用它, 教科书上也多半是"了解即可". 唯一还算正当的用途是从多层嵌套里一次性跳出来:

不过用标志变量也能达到同样效果, 所以很多规范(比如 MISRA C)干脆禁止使用 goto

有意思的是, Linux 内核代码里 goto 用得非常多, 主要用来做统一的错误清理. 所以"goto 一律有害"这个说法并不准确, 它在向前跳去清理资源这种场景下反而比嵌套 if 更清晰. 考试里按教科书答"少用/不用"即可

7 *循环与结构化

第 1 节提过"一个入口一个出口". 现在可以具体看看, 为什么 break 和 continue 不算破坏这个原则

关键区别在于 break 和 continue 的跳转目标是固定的:

  • continue 永远跳回当前这层循环的条件判断
  • break 永远跳到当前这层循环的后面

它们的落点由语法结构决定, 和代码里写了什么条件无关. 所以不管在循环体的哪个位置写 break, 都能一眼看出它会跳到哪儿

goto 就不一样了:

goto 的落点是一个任意的标号, 可能在前也可能在后, 可能跨越好几层循环和判断. 想知道控制流怎么走, 必须把整个函数通读一遍, 还得把所有 goto 的目标标号都找出来. 这就是"非结构化"的含义, 控制流的走向不再由缩进和嵌套结构决定

还有一个和它相关的编译期的情况, switch 的 case 值必须是编译期常量, 原因就在第 2.5 节提过的那句. 编译器要为 switch 生成一张跳转表(或者一串比较), 这张表在编译时就得排好. 而 if-else if 链是从上往下一路比较的, 所以它可以接受任意运行期表达式, 但选项多的时候要比较很多次. 这就是 switch 和 if-else if 在实现层面的真实差别
