10 *内存对齐

第 3 节那个 28 是巧合, 换成员顺序就未必了:

虽然 1 + 4 = 5, 但是实际变成了 8. 中间空出来的 3 个字节是填充

原因是 CPU 读内存不是一字节一字节读的, 而是一次读一个字(4 或 8 字节), 而且倾向于从对齐的地址开始读. int 放在 4 的倍数上, 一次就读出来; 放在奇地址上可能要读两次再拼

所以编译器主动插空白, 让每个成员都落在自己合适的边界上

具体有两条规则:

  1. 每个成员的起始偏移得是它自身大小的整数倍
  2. 整个结构体的大小是最大成员对齐值的整数倍

以 struct A 为例:

总大小 8, 是 4 的倍数, 合规

换个顺序:

还是 8, 但填充挪到结尾了:

结尾必须补齐, 否则数组里第二个元素的 i 就不对齐了

最亏的一种:

12 字节里只用了 6 个, 一半是空的

其他的一些例子:

结构体 成员 大小
char + int 1 + 4 8
int + char 4 + 1 8
char + char + char + int 1+1+1+4 8
char + int + char 1+4+1 12
double + char 8 + 1 16

记住”按最大的成员对齐”即可

真不想对齐有 #pragma pack(1) 这种指令, 嵌入式里做通信协议才用, 考试不考

11 *链表

有了 malloc 和二级指针, 链表就水到渠成了

如果你学过Python, 一定会非常怀念里面看似无限长度的列表

而C里面数组有一个问题, 大小是死的

链表不需要预先定大小, 要一个节点就申请一个, 用指针串起来:

节点就是第 7 节那个自引用结构体:

head 指向第一个, 最后一个的 next 是 NULL

建节点

malloc 的返回值必须检查, 这是指针提出的规矩

遍历

用了个 cur 而不是直接动 head, 因为外面还要用 head. 和遍历数组不能改原指针是一个道理

头插

形参是 Node **. 因为要改的是 head 本身, 写成 Node *head 改的只是副本, 外面不动

尾插

头插不用管后面, 尾插得先走到最后一个. 拿链表 1 -> 2 -> 3 插 4 演示一遍:

几个地方值得单独说:

cur = *head 为什么是 *head. 形参是 Node **head, 也就是”头指针的地址”. *head 才是头指针本身, 也就是指向第一个节点的那个东西. 想拿到第一个节点, 必须解一层

while (cur->next != NULL) 为什么不是 cur != NULL. 如果写成 cur != NULL, 循环会一直走到 cur 变成 NULL 才停, 那时 cur 是空指针, 再写 cur->next = n 就是解引用空指针, 直接崩. 要的是停在最后一个节点上, 所以判断的是它的 next

最后 cur->next = n 一句就够, 不用管 n->next. 因为 create 里已经把它设成 NULL 了

空链表那个分支不能省. *head 是 NULL 时进入循环, cur = *head 得到 NULL, 第一句 cur->next 就崩了

删除

所以要找的是”目标的前一个节点”. 但这就分两种情况了: 如果删的是头节点, 它前面没有节点, 得改 head 本身; 如果删的是中间节点, 改的是某个 next. 两者代码不一样, 写起来就得特判:

麻烦在于这两个分支的逻辑几乎一样, 只是”要改的那个东西”不同, 一个是 head, 一个是某节点的 next

next 字段和 head 其实是同类东西, 它们都存着指向某个节点的地址. 那能不能用一个指针, 同时管住这两种情况

能, 就是二级指针

cur 指的是”装节点地址的格子”, 而不是节点本身. 这个格子可能是 head 变量, 也可能是某个节点的 next 字段. 一旦想通这点, 两种情况就合并了

*cur = (*cur)->next 改的是格子的内容, 也就是让”某个 next”(或 head)指向下一个节点. 此时 [1] 的 next 从 [2] 变成了 [3], [2] 就被跳过了

free(tmp) 不能省, 也不能放在 *cur = ... 之前. 因为要先读出 (*cur)->next 来改, 如果先把 [2] 释放了, 再读它的 next 就是访问已释放的内存

删头节点的过程一模一样, 只是第一次循环就命中:

*cur 这时就是 head 变量, 所以 head 被直接改掉了. 这就是为什么删头不需要特判

cur = &(*cur)->next 这句容易看晕. 拆开读: (*cur) 是当前节点, (*cur)->next 是它的 next 字段, & 取这个字段的地址. 所以 cur 从”指着 head”变成”指着 [1] 的 next”, 再下一圈就变成”指着 [2] 的 next”

其余几个函数传进去的都是 const Student *, 只有 input 和 sort_by_score 没收 const, 因为它们真的要改数据 ## 13 猎奇小点

结尾的分号: struct X { ... }; 少一个分号, 后面全部报错, 而且报的位置看起来毫不相关

标签和类型名的区别: struct Student 里 Student 是标签, Stu 才是 typedef 出来的类型名. C 里两者不能混, 写了 Stu 就必须有对应的 typedef. C++ 能省 struct, 这里是 C

能赋值不能比较: a = b 合法(逐成员拷贝), a == b 编译错误. 填充字节里可能有垃圾, 没法整体比

匿名结构体: struct { int x; } a; 可以声明变量, 但这个类型没有名字, 别处没法再用

不能包含自身, 能包含自身指针: 前者大小算不出来, 后者固定 4 或 8 字节

sizeof 不等于成员之和: 对齐会插填充, 推导见第 10 节

共用体也要对齐: union { char c; double d; } 是 16 不是 8, 因为要按 double 对齐

枚举不是真的限制: enum Color c = 99; 编得过, C 的枚举没有类型检查, 只是给人看的约束

枚举常量不能赋值: RED = 5; 报 lvalue required, 它是编译期定死的符号, 不是变量

位段: struct { unsigned a : 3; unsigned b : 5; } 按位分配, 是另一种省空间的办法. 考试一般只考结论

-> 的由来: 就是 (*p).x 的简写. 那对括号太容易漏, 漏了变成 *(p.x), 报错信息还看不懂
