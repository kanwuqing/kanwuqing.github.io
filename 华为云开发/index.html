2026 华为开发者大赛（上海理工大学站）参赛方案分析报告

Kanwuqing1970-01-012026-10-16

赛题：开放型赛题 · 基于华为云码道 CodeArts 开发 AI 应用 报告日期：2026-10-11

一、赛题理解（基于官方完整赛题，非二手转述）

1.1 赛题定位

开放型赛题，围绕真实场景自选题目，不限创意内容与技术方向。鼓励五个方向：

编号 方向 典型形态
① 智能体与行业解决方案 办公纪要周报、教育答疑规划、垂直智能体、多智能体协作、RAG 问答
② AI+行业解决方案 智慧校园、社区民生、行程管家、IoT 农业监控、健康台账
③ 创意轻应用与互动工具 人流预测、活动报名、社团管理、校园地图、互动小游戏
④ 数据智能与可视化 实验数据自动可视化、日志分析、可视化大屏
⑤ 代码智能与开发辅助 报错排查、数据库设计辅助、代码审查、测试用例生成

1.2 硬性开发要求

  1. 作品必须原创，团队负全责。
  2. 开发过程必须使用华为云码道作为核心 AI 编程工具——本赛题唯一的「必须使用华为产品」条款。
  3. 作品形态限定：Web 应用 / 小程序 / 桌面工具，须可运行、可复现。
  4. 须提交码道使用痕迹证明：IDE 插件使用日志与操作记录、AI 交互对话与 Prompt 截图、代码生成/重构/排错过程记录。
  5. 侵权抄袭取消资格。

1.3 交付物清单（学生赛道初赛）

交付物 具体要求 约束
作品整体介绍 PPT/PDF 场景背景、功能架构、核心亮点、码道应用说明 命名「学生+作品名称+队伍名称+版本号+联系方式」，单文件 ≤20MB
功能演示视频 完整呈现核心功能操作流程 建议 ≤3 分钟，文件或在线链接
码道使用证明材料 AI 交互对话与 Prompt 截图、代码生成/重构/排错记录 ≤20MB
作品说明文档 WORD 环境依赖说明与一键安装脚本、部署运行步骤、开源组件说明、码道应用总结 ≤20MB
开发者作品展览馆网址 提交参赛项目后地址栏的网址 必交项
README（建议） 附 GitCode 仓库地址与作品展览馆发布链接 建议项

提交方式：校内 Welink 蒲公英表单 2026华为开发者大赛-上海理工大学站。 提交规则：可多次迭代，最终成绩取截止前历史最高提交版本。

1.4 评分标准

初赛（100 分，教师评委 50% + 专家评委 50%）

维度 分值 评审细则
功能完备度 30 核心业务完成度与可用性；逻辑顺畅、操作流畅；界面交互与用户体验专业度
码道深度使用 25 全流程覆盖度（环境搭建、代码生成、调试排错、文档生成）；Prompt 设计质量与工具使用效率；证明材料完整性与真实性
专业贴合与创新 25 贴合实际需求与落地合理性；差异化创新点；场景特色与行业洞察
技术架构与工程质量 15 技术选型合理、架构稳定；代码规范可维护；结合华为云其他服务提升能力
交付规范性 5 材料完整性、格式符合要求；文档清晰可按文档复现

决赛（100 分）

维度 分值 评审细则
作品核心质量 35 功能完整性、稳定性与交互体验；技术深度与架构合理性；专业场景匹配度与实用价值
码道应用深度 20 全流程创新用法与提效成果；对码道能力的理解与灵活运用；现场能否用码道快速调整功能与修复问题
现场演示与答辩 30 演示流畅、重点突出；讲解清晰、表达准确；问答准确、技术扎实；总时长 8 分钟（5 分钟介绍 + 3 分钟提问），超时扣分
创新与落地价值 15 创新点差异化与实用性；专业落地可行性；可拓展至更多场景

晋级规则：初赛前 31 支晋级决赛。决赛交付完善版安装包或在线演示地址（确保现场稳定运行）、正式答辩 PPT、完整源码与文档。可选实物演示联动加分。一等奖直通全国总决赛。

1.5 评分权重推论（决定所有后续决策）

  • 功能完备度 30 分是最大单项 → 功能要做得完、做得顺、做得好看，而不是技术炫技。
  • 码道深度 25 分是最容易系统化拿满的一档 → 属「过程分」，从第一天开始每日存证即可稳定拿下；反之最后一周补做必然拿不满。
  • 专业贴合与创新 25 分是最难的一档 → 需要真实痛点和差异化，靠「常见场景的简单实现」只能落 10–15 分。
  • 技术架构 15 分 → 常规工程规范 + 一句「结合华为云其他服务」。
  • 交付规范 5 分是纯白送分 → 四项文档写齐即得，丢失极不划算。
  • 决赛 30 分的现场演示答辩分，权重高于技术本身，演示稳定性必须按「不能失败」标准准备。

1.6 对早期信息的两点更正（重要）

前几轮分析中，我曾引用「演示环境需部署在华为云上」「与华为云结合越深度分越高」作为赛题要求，这两条均不在本赛题规则中，来源是另一分站赛的校内通知，属误引，已作废。以本报告为准：

  • ❌ 本赛题没有「演示环境必须部署在华为云」的硬要求。决赛只要求「安装包或在线演示地址」。
  • ❌ 本赛题没有「真实性/数据可追溯」评分维度。
  • ⚠️ 与华为云生态相关的只有两处：码道（25 分，主战场）、以及技术架构 15 分中的「结合华为云其他服务提升能力」（权重低，但不是零）。

二、选题决策

2.1 候选方案对比

维度 A. 垂直品类图鉴识别系统 B. 失物招领系统
实现难度 中高（识别准确率、拒识阈值、图集数据模型） 中低（CRUD + 搜索匹配）
技术风险 偏高：识别不准即演示翻车 低：但技术纵深不足
功能完备度 30 24–28：链路长、展示点多 24–28：直观易做流畅
码道深度 25 20–24：多模块多轮排错，痕迹素材天然丰富 20–24：过程太顺，Prompt 深度故事弱
专业贴合与创新 25 16–22：垂直识别 + 拒识 + 纠错闭环有差异化 10–16：成熟品类，差异化难讲
技术架构 15 13–15：对象存储、异步任务、模型服务 12–14：常规三层，无云服务结合点
交付规范 5 5 5
可扩展性 强：换品类即换图鉴，可平台化 中：限定单一场景
演示效果 强：拍照→秒出结果→生成图鉴 中：需预置数据，平淡
答辩说服力 强：准确率怎么测、拒识阈值怎么定、误识怎么纠 弱：8 分钟难撑技术含量
决赛现场码道调试 易出彩：改阈值、加筛选条件 一般：改动不显眼

2.2 决策：选 A

理由：A 与 B 在功能完备度、码道深度两个维度上差距不大，但在专业贴合与创新（25 分）上差距显著；而 B 的开发过程过于平顺，反而拿不到码道深度分所需的「代码生成、重构、排错过程记录」素材。A 的识别链路天然产生调参、排错、重构痕迹，是本赛题评分体系下的最优解。

三、最终方案

3.1 项目定位

项目名（建议）：「物候图鉴」——基于华为云码道开发的垂直品类识别与收藏 Agent

一句话描述：面向某垂直品类（校园植物 / 本地鸟类）的拍照识别与个人图鉴管理工具，具备识别、拒识、打标归档、图集管理、数据看板与知识问答完整闭环。

3.2 交付形态（关键决策）

形态：本地 Web 应用 + 便携包一键启动脚本，而非单文件安装包。

  • 后端：Python FastAPI，本机起服务（127.0.0.1:8000）
  • 前端：浏览器访问，Vue3 或原生 HTML+JS 单页
  • 启动：双击 start.bat / start.sh，自动装依赖、启服务、开浏览器

选择理由： 1. 界面体验远优于 Tkinter/PySide，「界面交互与用户体验专业度」是 30 分维度的明确条目。 2. 现场稳定性等同于 exe，且规避单文件 exe 冷启动慢、杀软误报、大模型文件解压慢的风险。 3. 代码可在需要时直接搬上服务器变成在线地址，不必重写。 4. 一键启动脚本本身就是「作品说明文档」要求的交付项，一举两得。

3.3 核心功能清单

模块 功能 对应评分点
用户体系 注册/登录、我的图鉴 功能完备度
上传 单张 + 批量拖拽、进度、失败重试 功能完备度
识别 Agent Top-K 候选 + 置信度 + 拒识（超范围明确告知不硬猜） 创新点
打标归档 自动打标 + 用户手动纠错闭环 创新点 + 体验专业度
图集管理 筛选、搜索、分组、导出 功能完备度
数据看板 识别量、品类分布、准确率 技术架构 + 方向④元素
知识问答 RAG：为什么是这个品种、与易混淆品种怎么区分 创新点 + 多 Agent
演示模式 内置示例图，网络/模型异常时不翻车 现场稳定性

3.4 技术栈

层 选型 说明
前端 Vue3 + Vite（或原生 HTML+JS） 移动端优先，拍照场景
后端 Python FastAPI AI 生态好，便于对接模型与云服务
模型 迁移学习轻量 CNN（MobileNet / EfficientNet 微调） 窄品类下易达 90%+
数据库 SQLite（便携）/ PostgreSQL 便携包优先 SQLite，零依赖
存储 本地文件系统 + OBS 适配器（可切换） 满足「结合华为云其他服务」
训练 本地跑为主 + ModelArts Notebook 可选运行 留截图与文档说明
开发工具 华为云码道 CodeArts（全程） 唯一硬性要求，必须留痕

3.5 数据集策略

采用开源数据集，不自行采集。

  • 候选：Oxford Flowers-102 / PlantVillage / LeafSnap（植物）、CUB-200-2011（鸟类）
  • 必做事项：
    1. 核查 License，在文档中标注来源与授权，规避侵权条款风险。
    2. 场景落差验证：用手机实拍 20 张同类照片测试准确率，量化「白底摆拍 → 真实拍摄」的性能下降。此结果决定演示时是现场拍照还是上传示例图。
    3. 记录预处理脚本与类别映射表，保证可复现。

3.6 华为云服务接入策略

优先级降低，但不可为零。 目标是投入 1.5 天，拿到 15 分维度中「结合华为云其他服务」的实据：

服务 投入 做法
OBS 0.5 天 存储适配器：本地 / OBS 可切换分支，代码里有真实调用路径
ModelArts 1 天 训练脚本在 Notebook 跑一次，留截图，文档写「支持本地与 ModelArts 双模式」

注意：仅把样本「复制一份到 OBS」是没有说服力的——评委看的是系统是否真的用到，不是文件是否躺在那儿。不做成的适配器则不接。

3.7 四阶段执行计划

第 1 周：打地基（不采数据，做三件正事） - 下载整理开源数据集 + 完成场景落差验证 - 码道搭建工程骨架，确立目录结构与模块划分 - 注册并发布一次「开发者作品展览馆」占位作品，把流程趟通（可能有审核周期） - 建立 docs/codearts-log/，按五类开始每日存证

第 2 周：核心链路 - 模型训练 + 推理接口 + Top-K + 拒识 - 上传界面、结果展示、打标入库、用户图集

第 3 周：完整度与云服务 - 图集管理、数据看板、RAG 问答（可选） - 接入 OBS 存储适配器（0.5 天）+ ModelArts 训练截图（1 天） - 便携包打包 + 一键启动脚本

第 4 周：交付与答辩 - 四件套：PPT（含码道应用说明）、说明文档 WORD（一键安装脚本/部署步骤/开源组件与 License/码道总结）、码道痕迹汇编、3 分钟演示视频 - README 附 GitCode 仓库地址 + 作品展览馆发布链接 - 答辩演练（5 分钟介绍 + 3 分钟提问）

3.8 码道留痕规范（对应 25 分，最高优先级）

从第 1 天开始，每日存证，分类归档：

每份记录保留：Prompt 原文 + 码道输出截图 + 最终代码文件路径。这套材料直接对应评分细则点名的「IDE 插件使用日志与操作记录」「AI 交互对话与 Prompt 截图」「代码生成、重构、排错过程记录」三项。

演示视频中预留 30 秒展示码道工作画面——这是评委最想看到的证据。

四、风险清单

等级 风险 应对
🔴 高 作品展览馆发布流程未走过，最后卡审核 第 1 周就发布占位作品趟流程
🔴 高 开源数据集与手机实拍风格落差大，演示翻车 第 1 周完成落差验证，据此确定演示方式
🔴 高 码道痕迹最后一周补做，25 分拿不满 每日存证，五类归档，从第一天开始
🟡 中 打包后换机器跑不起来 用便携包 + 一键启动脚本，不用单文件 exe；提前确认决赛设备
🟡 中 数据集 License 未标注，触发侵权条款 文档写明来源与授权
🟡 中 决赛 8 分钟超时扣分 演练固定到 5 分钟以内，留缓冲
🟢 低 华为云服务接入不足 1.5 天补 OBS 适配器 + ModelArts 截图

五、已确认的三项决策

# 决策 判定 补充动作
1 用开源数据集代替自行采集 ✅ 采纳 查 License、写进文档、做场景落差验证
2 本地训练模型，云服务后置 ⚠️ 部分采纳 云服务接入必须放在初赛提交之前，至少 OBS 适配器 + ModelArts 截图（约 1.5 天）
3 导出安装包替代在线网址 ⚠️ 改写 改为「便携包（本地 Web 应用）+ 一键启动脚本」；同时必须补齐作品展览馆发布页、3 分钟演示视频、现场码道调试预案

六、下一步立即可执行的三件事

  1. 定品类：在植物（Oxford Flowers-102 / PlantVillage）与鸟类（CUB-200-2011）之间二选一，优先选数据集 License 最清晰、类别边界最明确的。
  2. 发布占位作品：登录华为云开发者作品展览馆，发布一条占位记录拿到 URL，验证流程与审核周期。
  3. 建留痕目录：在 C:\Users\kwq\identify 下创建 docs/codearts-log/ 五类子目录，并写下第一条环境搭建记录，从今天开始积累码道证据。
