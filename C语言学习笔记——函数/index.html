返回值类型决定这个函数"算完之后给出什么东西". int add(...) 说明它给出一个整数. 如果函数只是干活、不需要交回结果, 就写 void:

void 的意思是"什么都不返回". 这种函数里不能写 return 值;, 只能写 return;(或者干脆不写)

参数列表是函数的入口. 上面 add 需要两个整数才能算, 就声明两个. 不需要任何输入的函数写成 (), 里面什么都不放

有个 C 语言的历史遗留问题: () 和 (void) 不是完全一样的意思

  • int f() 意思是"参数列表未指定", 编译器不检查传了几个参数
  • int f(void) 明确表示"没有任何参数", 传了参数就报错

严格说 (void) 更严谨, 但实际写代码时 () 用得更普遍, 看着也清爽. 考试和日常都用 () 就行, 知道即可

声明和定义的区别要记牢:

  • 声明(也叫函数原型)只介绍"有这么个函数, 长什么样", 不写函数体, 末尾是分号
  • 定义是完整实现, 带函数体

一个函数可以声明很多次, 但只能定义一次

实际写代码时, 只要把函数定义写在 main 之前, 就不用单独声明了, 因为编译器从上往下读, 到 main 时已经见过定义. 这是最省事的做法, 本书后面都这么写

顺带一说, #include <stdio.h> 引进来的 stdio.h 里全是函数声明. 之所以能直接用 printf, 就是因为头文件替我们打好了招呼

5 参数传递是"值传递"

这一节是整篇最重要的, 也是指针那篇要接着解决的问题

C 语言的参数传递只有一种方式: 值传递. 意思很简单, 实参的值被复制一份给形参, 函数里怎么改, 都只改那个副本

函数里把 a 改成 100, x 一点没变. 因为 a 只是 x 的一份拷贝, 改了拷贝动不了原件

语言这么设计是出于安全的考虑. 函数拿到的是一份拷贝, 就不可能悄悄改掉外面的变量. 要真正交换, 必须告诉函数"变量在哪儿", 也就是传地址. 这就是指针篇的内容:

这个方向先记着, 等看完指针篇再回头看这一节, 会特别清楚

"值传递"这个规则只有一个例外: 数组

数组作参数时, 传过去的是数组的地址, 不是整个数组的拷贝. 所以函数里改数组, 会影响外面的原数组

这不是规则被破坏了, 而是"数组名本身就代表地址", 传的仍然是"值", 只不过那个值恰好是个地址. 第 10 节会详细说

变量的"地盘"分两种:

局部变量定义在函数内部, 只有这个函数能用:

全局变量定义在所有函数外面, 所有函数都能用:

两者有一个关键差别, 在数据类型里提过: 局部变量不初始化是垃圾值, 全局变量不初始化自动是 0

全局变量看着方便, 但能不用就别用. 因为它对所有函数可见, 谁都能改, 出了问题很难查是哪个函数改的. 更实际的问题是: 全局变量会一直占着内存, 直到程序结束

局部变量和全局变量重名时, 局部的优先

这叫就近原则. 函数内部看得到自己的 x, 就不会去外面找. 全局那个 x 还在, 只是被挡住了

  • 生存期: 一个变量在运行时什么时候存在

大部分情况下两者是一致的, 但也有分开的时候(第 8 节的 static 就是)

10 数组作函数参数

这一节是为数组与字符串那篇铺路的, 因为数组最常干的事就是交给函数处理

数组可以传给函数, 形参有两种写法, 完全等价:

因为数组作参数时传的是地址, 不是整个数组的拷贝. 这和上一节说的"值传递"不矛盾, 传的确实是个"值", 只不过那个值是个地址

这就带来两个非常实用的后果:

第一, 函数里改数组, 外面的原数组跟着变. 这个性质虽然不是"值传递"的字面意思, 但极其有用:

如果数组是完整拷贝过去的, 这个函数就毫无意义了, 改完副本, 原数组还是原样. 正因为传的是地址, 它才能真的"清空"数组

第二, 函数里 sizeof 数组得不到正确结果:

函数里的 arr 已经不是数组了, 而是一个指针. sizeof 一个指针, 得到的自然是指针的大小(8 字节或 4 字节), 不是数组的大小

所以必须额外传一个长度参数. 这就是为什么所有数组处理函数的首部都是 (int arr[], int n) 这个样子, 那个 n 不是多余的, 是必需的

sizeof(arr) 在函数里得到 8 还是 4, 和机器的指针宽度有关. 我这里测的是 64 位环境, 所以得 8

考试环境是 32 位, 指针 4 字节, 那里会输出 4. 具体数值不重要, 关键记住"函数里 sizeof 数组 ≠ 数组真实大小"

12 *函数调用时的内存

前面反复说"值传递"“副本”, 这一节看看底层到底是什么样子, 这是理解递归和局部变量的关键

每次调用函数, 系统都会在栈上开辟一块专门的区域给这次调用用, 叫栈帧(stack frame). 里面放两样东西:

  • 这次调用的局部变量
  • 调用结束之后该回到哪里继续执行

拿 add(3, 4) 看:

内存里大致是这样:

main 里调用 add 的那一刻, 系统做了三件事:

  1. 把实参 3、4 复制进 add 的栈帧(这就是"值传递"在机器层面的样子, 实实在在的内存拷贝)
  2. 把"回来之后接着执行哪一行"记下来
  3. 跳到 add 的代码开始跑

add 跑完 return s 时, 反过来: 把 s 的值送回去, 然后把 add 的整个栈帧销毁, 按记下的返回地址跳回 main

这就是"局部变量出了函数就消失"的真正原因, 不是被清零了, 是整块地方被回收了. 再调用别的函数时, 那块地方会被重新利用, 所以在外面看到的"残留值"其实是别人留下的

也解释了为什么递归会栈溢出: 每递归一层就要新建一个栈帧, 而且上一层的不销毁(因为它还没算完, 等着下层返回), 层层堆叠, 栈空间用光就崩

数据类型里说过"局部变量没赋值是垃圾值", 现在知道垃圾从哪来了. 就是上一次用这块栈帧的函数留下的东西. 换台机器、改下代码, 栈的布局变了, 那个"垃圾"也跟着变

顺带说清 “值传递” 这个词的由来: 传的确实是值本身, 通过内存拷贝实现. 这也是为什么改形参动不了实参, 它们从一开始就是两块不同的内存
