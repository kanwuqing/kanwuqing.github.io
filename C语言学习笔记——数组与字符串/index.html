C语言学习笔记——数组与字符串

Kanwuqing2026-10-162026-10-16

流程控制那篇里, 猜数字游戏最多让用户猜 5 次. 要是把 max_try 改成 100, 循环本身没问题, 但”把用户猜过的数都存下来”这件事就做不到了 —— 总不能写 100 个变量 guess1 到 guess100

数据类型讲过, 一个变量就是一个盒子. 现在需要的是一排编好号的盒子, 用的时候拿编号去取. 这个东西就是数组

1 从”存100个数”说起

回到猜数字那个需求. 现在想让它记录每一次猜的数, 最后一起打印出来. 按数据类型的写法:

如果只猜 5 次, 忍忍也就过去了. 但需求一改成”最多猜 100 次”, 这个写法立刻崩溃. 而且就算真写了 100 个变量, 后面想遍历它们也没办法 —— 变量名不能拼出来, 你不能写 guess + i 来表示”第 i 个变量”

需要的东西满足三个条件: 一批同类型的盒子, 有连续的编号, 可以拿编号来访问. 这就是数组

int a[5] = {0}; 和 int a[5]; 看起来差不多, 前者是干净的全零, 后者全是随机数. 这个差别不写出来基本看不出来, 但对程序结果影响巨大

访问元素用下标, 下标从 0 开始:

a[5] 是最经典的错误: 5 个元素的数组, 合法下标是 0 到 4. 写 a[5] 编译器不会报错, 它会老老实实去算第 6 个位置的地址, 读出来的东西完全不可预测

C 语言不检查数组越界. 这是它”信任程序员”的一贯作风, 也是很多安全漏洞的来源. 考试里这类题就是问”程序输出什么”, 答案是”不确定”或”可能崩溃”

顺带说一句, a[5] 这种写法在语法上等价于 *(a + 5), 下标运算符 [] 本质上是指针运算的语法糖. 这一点第 11 节会讲清楚

3 数组在内存里是连续的

存储器与进制里说存储单元是按地址编号排的. 数组正好用到这一点: 它的所有元素在内存里紧挨着放

输出 20. 因为 int 占 4 字节, 5 个就是 20 字节

既然连续, 那就能用 sizeof 反推出长度:

sizeof(a) 是整个数组的大小, sizeof(a[0]) 是单个元素的大小, 一除就是元素个数. 这个写法在遍历和排序里很常用, 好处是改数组长度时不用改别的地方

连续存放带来一个实际好处: 知道第一个元素的地址, 就能算出任何一个元素的地址. 第 n 个元素的位置就是”首地址 + n × 元素大小”. 这正是下标访问能这么快的原因 —— 它不是一个个找过去的, 是直接算出来的

5 字符数组与字符串

C 语言里没有专门的”字符串类型”. 所谓字符串, 就是一串字符存在字符数组里

所以先要分清两个东西:

'a' 是一个 char, 占 1 字节. "a" 是两个字节 —— 除了 'a' 自己, 后面还跟着一个 \0

s1 是 6 字节, 因为双引号写法自动加了 \0. s2 只有 5 字节, 没有结束标志

而 strlen(s2) 打出个 10 —— 这个是错的. strlen 靠找 \0 来数长度, s2 里没有 \0, 它就一直往后读, 读到内存里别的地方的 0 才停. 这个 10 是碰巧读出来的垃圾, 换台机器或改下代码就变了

strlen 只认 \0, 不认数组长度. 对没有 \0 的字符数组用 strlen, 结果是未定义行为 —— 可能读到崩溃, 可能读出个莫名其妙的数字

同样地, 用 printf("%s", s2) 打印这种数组也会一路读下去, 直到撞见某个 \0. 这就是为什么用双引号初始化更省心 —— 它会自动补上结束标志

6 字符串的结束标志 \0

现在把 \0 单独说清楚, 因为它是字符串这一块的核心

\0 是数据类型转义字符表里的一个, 表示 ASCII 码为 0 的那个字符(不是字符 '0', 那个是 48). 它不可显示, 专门用来当字符串的结束标志

可以自己验一下:

单引号写法是 5 个字符, 双引号写法是 6 个字节, 多的那个就是 s[5], 值是 0

于是 C 语言里所有”字符串长度”的概念都有两种:

写法 含义 对 "hello" 的结果
sizeof(s) 数组占多少字节 6
strlen(s) 到 \0 为止有多少字符 5

strlen 不算 \0 本身, sizeof 算. 这个差别考得非常多

还有个更大的区别: sizeof 是运算符, 在编译时就算好了; strlen 是函数, 运行时才一个个数过去. 所以 sizeof 对指针只会给出指针本身的大小, 而 strlen 会老老实实去数

这个区别在实际写代码时很有用: sizeof(s) 用来当 fgets 的缓冲区大小上限, strlen(s) 用来处理真实内容. 用错了要么浪费要么溢出

7 字符串处理函数

C 标准库提供了一组字符串函数, 都在 <string.h> 里, 用之前要 #include

strlen 上面讲过了, 数到 \0 为止

strcpy 复制字符串:

它把右边的字符串(连同 \0)整个搬到左边. 注意不能用 a = "hello" 这种写法 —— 数组名不是变量, 不能整体赋值

strcat 拼接:

把 b 接到 a 的末尾. 前提是 a 装得下 —— strcat 不检查容量, 装不下就直接越界写

strcmp 比较:

它的返回值不是”真/假”, 而是三态:

  • 返回 0 表示两个字符串相等
  • 返回 负数 表示左边小
  • 返回 正数 表示左边大

两个字符串不能用 == 比较:

数组名 a 在表达式里会变成首地址. 所以 a == b 比的是”两个数组是不是同一个位置”, 当然是假. 要比较内容必须用 strcmp

判断 strcmp 的结果时, 不要写 == 1 或 == -1. 标准只保证”正/零/负”, 具体是 1 还是 27 由实现决定. 写 strcmp(a,b) > 0 才稳妥

比较规则是从左往右逐字符比 ASCII 码, 第一个不同的字符定胜负. 如果前面全一样, 那就长的那个更大

输出字符串有 puts, 输入有 gets 和 fgets

gets 读一整行. 它有个致命问题 —— 不检查缓冲区大小:

只要输入够长, gets 就会一直往后写, 把相邻内存覆盖掉. 这个漏洞太严重, 所以 C11 标准已经把 gets 删掉了. 但考试环境(VC++ 2010)还认它, 考试里照写能过

fgets 有个和 gets 不一样的地方: 它会把换行符也读进去

9 数组作函数参数

数组可以传给函数. 但传的是地址, 不是整个数组的副本, 这一点必须搞清

形参写成 int arr[] 或者 int *arr 都行, 两者完全等价. 因为传进来的本来就是个地址

这就带来两个重要后果:

第一, 函数里改数组, 会影响原来的数组:

因为函数拿到的是地址, 顺着地址改的就是原来那块内存

第二, 函数里 sizeof 数组得不到正确结果:

函数里的 arr 已经不是数组, 而是一个指针. sizeof 一个指针得到的自然是指针的大小. 所以必须额外传一个长度参数, 就是上面 print(int arr[], int n) 里那个 n 的来历

sizeof(arr) 在函数里得到 8 还是 4, 取决于目标平台的指针宽度. 我这里测的是 64 位环境, 所以是 8

你的考试环境是 32 位, 指针是 4 字节, 那里会输出 4. 值不重要, 关键是”函数里 sizeof 数组 ≠ 数组真实大小”这件事

11 拓展: 数组名到底是什么

运算符那篇提过 &(取地址)和 sizeof, 这里把它们和数组名串起来

先做个测试:

输出是 1, 也就是“第一个元素的地址”和”数组名”相等. 所以数组名在大多数场合就是首地址

这也解释了 a[0] 为什么是第一个元素 —— 下标从 0 开始, 因为它是”从首地址偏移 0 个元素”

下标运算符 [] 的本质是加法:

a 是首地址, +i 往后偏移 i 个元素, * 取出那个位置的值. 既然是加法, 那交换顺序也一样:

2[a] 能编译过, 就是因为它等价于 *(2 + a). 这个写法只适合拿来确认理解, 实际代码里别用

但数组名和普通指针有一个关键差别: 数组名是常量, 不能被赋值

还有一处例外, 就是sizeof 和 &:

sizeof(a) 得 20, 说明在 sizeof 眼里 a 是整个数组, 而不是”一个地址”. 这是数组名”退化”成指针规则的两个例外之一(另一个是 &a). 前面第 9 节函数参数里 sizeof(arr) 只有 8, 就是因为作为函数参数时数组名已经退化成指针了, 不受这条例外保护

所谓”退化”(decay), 指的就是数组名在表达式里自动变成指向首元素的指针. 记住有三件事是例外: sizeof、&、以及用字符串字面量初始化数组. 其余场合, 数组名都当指针用
