数组与字符串那篇最后一节提到数组名在表达式里会自动变成”指向首元素的指针”, 但当时只说了这个现象, 没说指针本身是什么

很多人都觉得指针难, 指针确实难不然也不会在某些语言内被删了, 主要是难在”它有两个值”: 指针自己有个值(地址), 它指向的地方还有个值. 两个值之间经常容易串线. 但只要始终分清”说的是哪一个”, 指针其实没有玄学

1 内存与地址

存储器与进制那篇说过, 内存是一排编了号的小格子, 每个格子一个字节, 每个字节有个编号, 这个编号叫地址

这一行在内存里做的事是: 找 4 个连续的格子(因为 int 是 4 字节), 把 10 的二进制写进去, 然后给这 4 个格子的第一个编个号

a 的地址就是 0x1000, 也就是它第一个字节的地址. 用 &a 能把这个地址取出来:

%p 是专门打地址的格式符, 输出十六进制. 具体那串数字每次运行都可能不同, 因为系统每次把变量放在哪儿并不固定, 这跟操作系统和编译器的安排有关

我这里的地址是 12 位十六进制(48 位有效), 因为跑在 64 位系统上. 若是 32 位, 打印出来就是 8 位十六进制(32 位), 比如 0012FF7C. 位数不同不影响任何结论

2 指针变量的本质

地址本身是个整数, 就能把它存起来, 存地址的变量就叫指针

拆开看 int *p = &a; 这一行:

  • int * 是类型, 意思是”指向 int 的指针”
  • p 是变量名
  • &a 是初值, 也就是 a 的地址

所以 p 符合数据类型那篇说的”变量 = 类型 + 名称 + 值”, 只不过它的值是别人的地址

内存里长这样:

p 自己也有地址(&p), 但它存的值是 a 的地址. 这就有了两个层次:

写法 含义 值
p 指针自己的值 a 的地址
*p 指针指向的东西 10
&p 指针自己的地址(目前不太用) 另一个地址

分不清的时候, 先问”我要的是地址还是地址里的东西”, 大多数指针错误都是因为把这俩货混起来了

* 两个数之间 乘法

*p 不只是”读”, 也能”写”:

*p = 99 的意思是”往 p 指向的那个地方写入 99”. 那个地方就是 a, 所以 a 跟着变了

这是指针的第一个真正威力: 通过一个变量, 改到了另一个变量

4 指针的类型与长度

指针也有类型, int * 和 char * 是不同的类型. 类型决定了三件事

第一, 指向的东西解释类型

同一块内存, 换个指针类型去看, 读出来的东西就不一样. 后面数据类型那篇讲过的”同一串二进制按 int 和按 float 解释结果完全不同”, 这里就是它的实际用法

第二, 指针加 1 按类型解释

int * 加 1 走 4 个字节, char * 加 1 走 1 个字节. 这不是随便定的, 加 1 的意思是”走一个元素”, 而元素多大由类型决定

第三, 指针自己占几个字节

全都是同一个数. 因为指针存的都是地址, 而地址的长度由地址总线的宽度决定, 跟它指向什么无关

考试环境是 32 位, 上面三个都会输出 4. 记住这个结论: 指针长度固定, 和指向的类型无关; 32 位系统 4 字节, 64 位系统 8 字节

顺带解释一个曾经的疑惑: 为什么 (sizeof(p) == 8) 但 sizeof(*p) == 4(当 p 是 int *). 因为前者量的是指针本身, 后者量的是它指向的东西

比较

比较的是地址的大小或相等. 注意只有指向同一块区域的指针比较才有意义, 比较两个不相干变量的地址, 结果不可靠

7 指针作函数参数

这一节回收函数那篇埋的伏笔

那篇反复讲”值传递”: 函数拿到的是一份副本, 改副本动不了原件

用指针就能真换. 思路是: 不传变量的副本, 传变量的地址, 让函数顺着地址回去改原件

关键在于调用时要传地址(&x、&y), 函数里解引用后赋值(*a = *b)

swap(x, y) 漏了 & 是最常见的写法错误. 编译器一般会警告, 但如果硬编译过去, 运行时就会去访问 1 和 2 这两个地址, 会直接崩

写的时候记一句: 函数形参是指针, 调用就得给地址

9 指针数组与数组指针

这两个名字几乎一样, 但完全是两种东西. 区分的方法只有一个: 看括号

写法 名字 本质
int *p[3] 指针数组 一个装了 3 哥个指针数组
int (*p)[3] 数组指针 一个指针, 指向一个 3 元素的数组

规则很简单: [] 的优先级比 * 高, 所以 int *p[3] 先结合成”p 是 3 元素的数组”, 再说是”装指针的数组”. 加括号强行改结合顺序, 就变成”p 是指针, 指向 3 元素的数组”

12 *堆与栈, 以及野指针

这是个上限极高的操作, 它使得内存支配, 尽在手中

函数第 12 节讲过栈帧: 每次调用函数就在栈上开一块, 函数返回就销毁. 现在把另一块内存也讲了, 这件事才算完整

栈和堆的区别

栈 (stack) 堆 (heap)
谁分配 编译器自动 程序员手动 malloc
谁释放 函数返回时自动 手动 free
大小 小(通常几 MB) 大(受限于物理内存)
速度 快 慢一些
存什么 局部变量、参数 需要”活过函数”的数据

一句话概括: 栈上的东西会自己消失, 堆上的东西要自己管

malloc 和 free

四个要点:

第一, malloc 的参数是字节数, 所以常写成 n * sizeof(int):

第二, 一定检查返回值. 内存不够时 malloc 返回 NULL, 不检查就直接解引用, 就是下一段要说的崩溃

第三, free 之后指针不会自动变 NULL. 它还是指着原来那个地址, 但那块内存已经不再属于这段程序

第四, free 之后立刻置 NULL. 这是个几乎不需要成本的好习惯, 能防住后面一大类错误

悬垂指针 指向的内存已经释放/失效 有时能跑, 有时崩

14 指针的易错点

这一篇的坑比较多, 集中列一下

一、int *p 没说指向哪

定义指针时要么给个真实地址, 要么给 NULL

二、*p++ 和 (*p)++ 不是一回事

*p++ 的实际含义是 *(p++): 先取当前位置的值, 再把指针往后挪. 这一句单独写的话, 取出来的值被丢掉了, 只有 p 变了

三、sizeof(指针) 和 sizeof(数组) 差别很大

这个坑在函数第 10 节就出现了: 数组传进函数后 sizeof 就不准了

四、char * 指向字面量不能改

要改就用 char s[] = "hello";

五、free 之后继续用

六、同一个指针 free 两次

这也是为什么 free 之后要置 NULL: 对 NULL 调 free 是安全的(什么都不做)

七、指针相减只对同一块区域有意义

15 猎奇小点

NULL: 标准里定义成 ((void *)0), 本质就是地址 0. #include <stdio.h> 或 <stdlib.h> 都能拿到它

p == NULL 和 !p 等价: 因为 NULL 是 0, 就是假. 两种写法都常见

指针的两种”空”: NULL(明确的空)和未初始化(垃圾). 前者安全可判断, 后者容易悄悄搞事情

void * 是通用指针: 可以指向任何类型, 但不能直接解引用, 必须先转成具体类型. malloc 返回的就是它

32 位和 64 位的区别: 指针 4 字节 vs 8 字节. 考试一律按 4 字节算

int *p, q; 只有 p 是指针, q 是 int. * 只管紧跟着的那一个变量. 想两个都是指针得写成 int *p, *q;

数组名不是指针: 虽然大部分场合行为像, 但 sizeof 和 & 时不一样, 而且数组名不能被赋值

&a 和 &a[0] 的区别: 值相同(都是首字节地址), 但类型不同. &a 是 int (*)[5], &a[0] 是 int *. 加 1 之后就走散了: &a + 1 跳过整个数组 20 字节, &a[0] + 1 只走 4 字节

函数指针: int (*f)(int, int) 是指向函数的指针, 而非返回指针的函数, 指向的是代码区地址. 考纲一般不深入, 知道写法即可

const int *p 和 int * const p: 前者是”指向常量的指针”(不能改 *p, 能改 p), 后者是”常量指针”(能改 *p, 不能改 p). 从右往左读: const 挨着谁就锁谁

指针这个工具单独拿在手里, 能做的事其实有限, 它真正的用处要配上一个自定义的复合类型才能发挥出来. 下一篇结构体与共用体就做这件事, 那里会写出真正的链表
